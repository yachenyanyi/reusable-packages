# 发现项与处置闭环（Finding & Case Center）

## 目的

把机器发现转变为可由人确认、分派、整改和复查的工作对象，并保存完整状态历史。

## 公开能力

- 接收分析引擎产生的 Finding。
- 合并或关联重复发现项。
- 确认、驳回、分派和标记处理。
- 发起复查并记录复查结论。
- 查询问题状态与处理时间线。

## 状态模型

```text
待确认 → 待处理 → 已处理 → 已复查
   └──→ 已驳回
```

状态转换必须由明确命令触发，并记录操作者、理由、时间和证据。

## 不变量

- Finding 是检测事实，Case 是业务处置；两者不能混为一条可覆盖记录。
- AI 不得绕过人工确认执行删除或外部整改。
- 复查必须引用新的 Observation 或人工证据。
- 已关闭 Case 的历史不得删除或改写。

## 隐藏知识

重复项合并、状态机校验、分派规则、整改渠道和主站 CMS 集成细节。

## 非目标

不执行内容采集和分析，不负责报告排版或通知渠道发送。
