# 可复用内容监测架构

本目录采用“一模块一文档”。目标不是增加层数，而是通过少数深模块隐藏采集、重试、版本、供应商和存储细节，使不同外部信息监测场景共享稳定底座。整体愿景和领域语言见 [foundation](../foundation/01-愿景与边界.md)。

## 核心数据链

```text
Run → Observation → Document → Snapshot → ChangeEvent
```

`Task` 可以由可选任务模块提供，也可以直接由宿主产生 `RunRequest`。`Item`、`Attempt` 是采集引擎内部模型。`Finding`、`Case`、`Report`、`Alert` 属于可选扩展。

## 模块关系

```text
宿主平台 / 独立运行包
              ↓
  场景映射 / 任务 / 分析等扩展
              ↓
      采集引擎 → 内容历史
          ↓          ↓
       上游任务、存储与事件端口
                 ↓
              适配器
```

审计事实和运行可观测性是核心钩子；身份权限、套餐、调度入口属于宿主集成。数据库、队列、对象存储和第三方客户端只能通过适配边界接入。

## 模块归属

- 核心必需：采集引擎、采集执行运行时、内容历史，以及它们使用的领域契约和端口。
- 可选扩展：数据源资产目录、任务中心、数据源映射、分析、Finding/Case、报告、预警和三个场景模块。
- 宿主集成：身份权限、套餐/额度映射、平台调度入口与具体项目装配。
- 基础设施适配：统一采集 API、数据库、对象存储、队列和运行器实现。

## 依赖原则

1. 业务场景依赖共享核心，共享核心不依赖具体业务场景。
2. 调用方表达意图，不协调 URL 发现、抓取、解析、重试和存储步骤。
3. 领域模块不接触 ORM、HTTP 响应、队列消息或供应商 DTO。
4. 原始证据不可覆盖；Run 启动时冻结实际使用的配置版本。
5. 默认采用模块化单体和独立 Worker；具体调度、队列和存储产品由项目规模决定，不改变领域接口。

## 当前非目标

- 不提前拆分微服务。
- 不建设万能规则语言或插件市场。
- 不把所有来源差异塞进一个无结构 JSON。
- 不绕过登录、验证码、访问控制或站点安全限制。
