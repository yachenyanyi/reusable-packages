# 运行可观测性（Runtime Observability）

## 目的

让维护者能够判断系统是否健康、故障发生在哪里、影响了哪些任务和来源。

## 能力范围

- 结构化日志与关联 ID。
- 运行指标：吞吐、延迟、失败率、重试率、队列积压。
- 来源健康：连续失败、429、解析结果骤降、正文为空。
- 告警：Worker 停止、存储异常、任务超时和错误率突增。
- 分布式追踪按实际复杂度后续引入。

核心只提供可选 `TelemetrySink` 钩子，不绑定日志、指标或告警产品。钩子属性只包含范围和运行关联标识，不包含密钥和正文。

## 关联标识

日志和指标至少能关联 `source_id`、`task_id`、`run_id`、`item_id` 和 `attempt_id`，但不能包含密钥和大段正文。

## 不变量

- 业务失败和系统故障必须可区分。
- 指标不可成为业务事实的唯一存储。
- 监控系统故障不能阻塞核心采集结果落库。

## 隐藏知识

日志供应商、指标后端、采样率、告警平台和保留策略。

## 非目标

不保存业务审计，不决定任务重试，不修改采集状态。
