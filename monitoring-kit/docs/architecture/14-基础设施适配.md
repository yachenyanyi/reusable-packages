# 基础设施适配（Infrastructure Adapters）

## 目的

隔离数据库、队列、对象存储、调度器和第三方客户端，使领域模块依赖稳定能力而非具体产品。

## 适配边界

- 事务数据存储：PostgreSQL/MySQL 等。
- 原始证据存储：MinIO/S3/文件系统。
- 异步运行：进程内任务、Celery/Redis 等。
- 调度：APScheduler、Celery Beat 或其它实现。
- 外部客户端：LLM、消息渠道、主站 CMS。

## 演进建议

- 百级来源、低频运行时，可先采用轻量调度器和数据库状态表。
- 当出现多 Worker、明显队列积压、跨节点恢复需求时，再迁移到 Celery/Redis。
- 迁移不得改变任务中心和采集引擎的领域接口。

## 不变量

- ORM 模型、队列消息和供应商 DTO 不进入领域模块。
- 基础设施异常被翻译为上层可处理的稳定错误。
- 密钥来自安全配置或密钥存储，不硬编码。

## 非目标

不承载业务规则，不定义 Run 状态机，不把每个库简单包一层同名 Service。
