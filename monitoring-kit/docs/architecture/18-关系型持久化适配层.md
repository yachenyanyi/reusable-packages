# 关系型持久化适配层（Relational Persistence Adapter）

## 目的

关系型持久化适配层为核心提供可替换的 `RunStateStore` 和 `HistoryStore` 实现。它把数据库连接、schema、领域对象编码、事务、幂等记录、连接生命周期及 SQLite/MySQL 方言差异封装起来，让核心和宿主只面对已有的领域端口。

详细的方案比较、实施顺序和测试清单见 [v0.2 关系型持久化适配层开发简报](../foundation/12-v0.2关系型持久化适配层开发简报.md)。

## 装配接口

```text
PersistenceConfig(database_url, ...)
open_persistence(config) -> PersistenceBundle

PersistenceBundle
├─ run_state_store: RunStateStore
├─ history_store: HistoryStore
└─ close() -> None
```

应用装配层拥有 `PersistenceConfig` 和 bundle 生命周期。数据库类型只由 `database_url` 决定，应用不应同时传入相互竞争的 `backend` 选择参数。`safe_url` 可供诊断使用，但必须脱敏密码。

核心通过已存在的 `RunStateStore` 与 `HistoryStore` 端口使用 bundle 内的 Store，不依赖 bundle、SQLAlchemy 或任何数据库类型。

## 适配层拥有的知识

- SQLAlchemy Core、数据库 URL、连接池、连接关闭与数据库异常翻译；
- schema、表、索引、schema version 和前向 schema 升级；
- 领域契约与关系型记录之间的编码、解码与 UTC 时间处理；
- `HistoryStore.commit` 的本地事务、`ingest_key` 幂等记录与可重放结果；
- SQLite/MySQL 的连接行为、锁与 Run 领取细节。

这些知识不得进入 `collection/`、`history/`、`contracts/`、`extensions/` 或宿主业务代码。

## 不变量

- `HistoryStore.commit` 中的 Document/current 指针、Snapshot、ChangeEvent、幂等记录和可重放结果必须同事务提交。
- 同一 `scope_key + ingest_key` 重放不得重复生成历史事实。
- 运行推进遵循“历史先提交、Run/cursor 后保存”；两个 Store 不建立跨 Store 的全局事务。
- `allocate` 的租约写入必须原子化；有效租约内，同一 Run 不被多个 worker 同时领取。旧的 `claim_runnable` 只作为兼容入口。
- `allocate` 必须先锁定共享 allocator state，再读取 active 计数；公平游标使用等待锁，不能因为 `SKIP LOCKED` 跳过唯一状态行。候选读取不能被批次大小提前截断，以免饱和 gateway 隐藏后续可用 Run。
- Run 状态保存使用适配器内部的单调 `state_version` 做 CAS；租约过期后被重新领取的旧 Worker 不能覆盖新状态。版本不进入 `RunSummary`。
- `HistoryWrite` 携带计算所依据的旧 Document；关系型事务锁定当前 Document 后比较，冲突由 `ContentHistory` 有限次重读并重新计算。
- 变化查询把 scope、过滤条件、游标和 `limit + 1` 下推到 SQL；下一页游标指向当前页最后一条事件，不会跳过预读行。
- 连接串、密码和底层数据库异常不进入日志、Telemetry、审计或稳定错误文本。

## 方言边界

共享 schema、codec、读写语义和错误翻译位于 `adapters/persistence/relational/`。仅当无法共享时，SQLite/MySQL 的差异放入私有 `dialects/`，目前主要是连接与并发领取算法；公平游标的等待锁与候选行的跳锁是两个不同意图，不能混用。

schema 初始化的临界区也留在适配器内部：SQLite 使用数据库写锁，MySQL 使用数据库级 advisory lock。新建 MySQL 表使用 InnoDB 与 `utf8mb4`，JSON 载荷使用 `LONGTEXT` 方言变体；SQLite 仍使用共享文本类型。

`RunRequest.fingerprint()` 是固定长度的 SHA-256 摘要，完整请求仍保存在 Run 载荷中。`PersistenceConfig.safe_url` 默认移除全部 query 参数并隐藏密码；无法解析的连接串只返回固定占位文本。

`ClaimStrategy` 如果存在，是私有实现细节；核心不选择它，也不为它提供公开扩展接口。新增 PostgreSQL 等关系型数据库时，应增加私有方言实现并运行同一份 Store 语义测试。

## 非目标

- 不把表模型、SQL、事务或 Session 作为公开 API。
- 不为每张表增加通用 CRUD/Repository 抽象。
- 不实现跨 SQLite/MySQL 的自动数据搬迁；它和同库 schema migration 是不同问题。
- 不为尚未发生的 schema 变化提前绑定迁移框架。

本轮已增加关系型载荷解码错误的统一分类：损坏的 Document、Snapshot、ChangeEvent 或 HistoryResult 不会把原始 `KeyError`、JSON 异常或数据库行泄漏给核心。
