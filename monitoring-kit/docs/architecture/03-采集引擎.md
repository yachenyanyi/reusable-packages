# 采集引擎（Collection Engine）

## 目的

作为最深的核心模块，把一次任务可靠地完成；隐藏 Run、Item、Attempt 的协调，以及适配器、执行器、重试和结果提交顺序。

## 最小公开接口

```text
submit_run(RunRequest, ExecutionContext) → RunRef
cancel_run(run_id, ExecutionContext)     → CancellationResult
get_run(run_id, scope_key)               → RunSummary
query_changes(ChangeQuery, scope_key)    → ChangePage
```

运行宿主额外调用：

```text
wake(limit)                 → WorkSummary
recover_interrupted_runs()  → RecoverySummary
```

`submit_run` 只接受请求并排队，不隐式创建后台线程；独立运行器或宿主 Worker 显式调用 `wake`。`RunRequest` 不包含重试次数、HTTP 客户端、队列名、浏览器或存储位置。

## 内部职责

- 校验已注册的场景规格和来源引用能否运行。
- 防止不允许的重复并发。
- 创建和推进 Run、Item、Attempt 状态机。
- 选择并调用数据源适配器。
- 通过 `UpstreamJobGateway` 处理外部任务协议；引擎自身统一协调轮询、重试、回退和结果提交顺序。
- 建立内部 Run 与上游任务 ID 的稳定关联。
- 跟踪上游任务状态，消费部分结果，并在终态后完成结果核对。
- 将成功观察提交给内容历史。
- 汇总完成、错误和变化统计。

## 状态约束

- Run：待执行、运行中、完成、完成但有错误、失败、取消。
- Item：待处理、处理中、等待重试、完成、最终失败、跳过、取消。
- Attempt：进行中、成功、失败、取消。
- 只要仍有 Item 等待重试，Run 就不是终态。

## 隐藏知识

内部调用顺序、幂等提交、轮询与事件协同、游标推进、结果核对、重试和回退、锁和并发、消息格式、事务边界、框架异常及 Attempt 明细。

## 非目标

不包含特定网站选择器，不判断风险，不生成报告，不暴露底层 HTTP 状态给业务调用方。

## 依赖与使用方

由宿主或任务扩展调用；依赖场景采集适配器、上游任务网关、内容历史、运行状态端口，以及可选的审计和可观测性钩子。
