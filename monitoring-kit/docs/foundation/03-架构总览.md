# 架构总览

## 代码库分层

```text
┌──────────────────── 宿主集成 Host Integrations ────────────────────┐
│ 现有平台 │ 独立 CLI/API │ 平台身份/套餐/调度映射 │ 项目装配          │
└──────────────────────────────┬─────────────────────────────────────┘
                               ↓ 依赖
┌──────────────────── 可选扩展 Optional Extensions ─────────────────┐
│ 任务目录 │ 站点/GEO/舆情映射 │ 分析 │ Finding/Case │ 报告 │ 预警 │
└──────────────────────────────┬─────────────────────────────────────┘
                               ↓ 依赖
┌────────────────────── monitoring-kit core ────────────────────────┐
│ Contracts                                                          │
│   RunRequest / RunSummary / Observation / Snapshot / ChangeEvent   │
│                                                                    │
│ Collection Engine ──→ Content History                              │
│   提交、恢复、核对       身份、去重、快照、变化                     │
│                                                                    │
│ Ports                                                              │
│   UpstreamJobGateway / StateRepository / ArtifactStore / EventSink │
└──────────────────────────────┬─────────────────────────────────────┘
                               ↓ 实现
┌──────────────────────── Adapters ──────────────────────────────────┐
│ 统一采集 API │ PostgreSQL/SQLite │ S3/文件系统 │ 进程内/队列运行器   │
└────────────────────────────────────────────────────────────────────┘
```

依赖只能向下。核心不知道正在运行长三角、GEO 还是舆情项目，也不知道调用者是单机程序还是多用户平台。

## 选择模块化单体

这里的“模块”首先是包和契约边界，不代表独立服务。默认以库的形式被宿主装配；独立运行包只是其中一个宿主实现。

## 最深模块

采集引擎是当前最深模块。它对外只有提交、取消、恢复和查询运行摘要等少量意图接口；内部隐藏 Run、Attempt 状态、统一 API 任务关联、重试、回退、游标、并发和结果核对顺序。

内容历史是另一个深模块。调用方提交 Observation，它内部负责身份解析、去重、快照、哈希、删除候选和变化事件。

## 数据链与可见性

```text
宿主/扩展： Task ────────────────→ Finding / Case / Report / Alert
                         ↑                         ↑
核心公开： Run → Observation → Document → Snapshot → ChangeEvent
                  ↑
核心内部：     Item / Attempt / cursor checkpoint
```

核心稳定链到 `ChangeEvent` 为止。`Finding`、`Case`、`Report` 和 `Alert` 是可选扩展，不是核心完成一次监测运行的前提。
