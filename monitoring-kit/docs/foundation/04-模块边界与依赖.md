# 模块边界与依赖

## 依赖方向

```text
宿主平台 / 独立运行包
              ↓
场景与可选扩展（任务、分析、报告、预警）
              ↓
核心契约 → 采集引擎 → 内容历史
              ↓           ↓
         上游任务端口   持久化/证据/事件端口
              ↓           ↓
                 具体适配器实现
```

宿主、扩展和适配器都依赖核心；核心不反向依赖它们。核心不得依赖 FastAPI、ORM、Celery、具体数据库、供应商 SDK 或平台用户模型。

## 模块为何拆分

- 核心契约定义跨项目必须稳定的语言，不承载实现步骤。
- 采集引擎隐藏一次 Run 的可靠执行和上游任务协议。
- 内容历史隐藏身份解析、版本和变化判定。
- 端口表达核心真正需要的能力，适配器隐藏技术产品差异。
- 数据源映射、分析、Case、报告和预警分别隐藏各自易变的业务知识。
- 宿主集成隐藏平台的用户、套餐、权限、调度和装配方式。

这些模块按不同“易变知识”拆分，不按代码执行先后机械地拆成 parser、validator、processor 等浅层模块。

## 接口规则

- 名称表达调用者意图，如“启动运行”“记录观察”，不表达 SQL、HTTP 或队列动作。
- 输入输出使用领域类型，不传 ORM 对象、Response、消息载荷或供应商异常。
- 调用者不负责重试、清理、事务或固定调用顺序。
- 布尔开关只用于真正二元状态；明显改变行为的选择使用领域类型或独立命令。
- 只暴露调用者能处理的错误。

## 模块协作

同进程内优先直接调用稳定接口。需要削峰、重试或异步隔离时可以使用内部事件/队列，但消息结构仍由领域事件定义，不能让消息中间件格式成为领域接口。

核心稳定事件只包括 `RunCompleted`、`ObservationRecorded` 和 `ContentChanged`。`FindingCreated`、`CaseStatusChanged` 属于扩展事件。

## 禁止依赖

- 共享核心不得导入站点、GEO 或舆情业务模块。
- 共享核心不得导入宿主平台的用户、租户、套餐、权限或通知模型。
- 业务模块不得直接调用具体 HTTP、LLM、数据库或消息供应商。
- 报告和预警不得反向修改采集流程。
- 适配器不得自行推进 Run 或 Case 状态。

## 最小稳定接口

核心第一版只承诺以下公共能力：

```text
submitRun(request, context) → RunRef
cancelRun(run_id)           → CancellationResult
getRun(run_id)              → RunSummary
queryChanges(query)         → ChangePage
```

`context` 只含 `scope_key`、`actor_ref`、幂等键和可选执行限制。轮询、游标、Attempt、回退策略和数据库事务不进入调用者接口。运行宿主与扩展适配器使用的接口见 [公共 API 与扩展 SPI](09-公共API与扩展SPI.md)。
