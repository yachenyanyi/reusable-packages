# 愿景与边界

## 愿景

建设一套可嵌入、也可独立运行的“外部信息持续观察代码库”：它能从统一采集 API 获取数据，保留可信证据和历史版本，识别变化，并把稳定事件交给不同业务场景使用。

核心价值不是“能爬网页”，而是让外部世界的变化稳定、可追溯地进入内部系统。

## 稳定主链

```text
定义来源 → 定义任务 → 执行观察 → 留存版本
        → 识别变化 → 分析发现 → 处置 / 报告 / 预警
```

## 当前验证场景

- 站点监测：网页新增、更新、删除、失联和整改复查。
- GEO 效果监测：模型回答、品牌提及、位置和引用变化。
- 舆情监控：帖子、新闻、话题、情感和传播变化。

未来可以接入价格监测、政策监测、竞品情报等场景，但不会为尚未出现的需求提前设计业务模型。

## 核心代码库范围

- 稳定领域契约：运行、观察、文档、快照和变化事件。
- 上游任务提交、状态跟踪、游标恢复、幂等和结果核对。
- 原始证据引用、内容身份、版本历史和变化判定。
- 存储、上游 API、时间和运行唤醒等端口。
- 最小运行查询、审计事实和可观测性钩子。

## 可选扩展范围

- 数据源资产目录和长期任务定义。
- 规则或 AI 分析、Finding 与人工处置。
- 报告生成和预警通知。
- 站点、GEO、舆情等场景模型与字段映射。

这些能力可以随代码库发布，但不能成为核心采集与历史能力的反向依赖。

## 宿主系统范围

- 用户、组织、租户、角色和登录。
- 套餐、订单、额度购买和平台 UI。
- 平台调度入口、消息中心和业务审批。

核心只接受不透明的 `scope_key`、`actor_ref` 和可选的 `ExecutionLimits`，不理解套餐名称、支付状态或平台权限模型。

## 非目标

- 不建设全互联网搜索引擎。
- 不绕过登录、验证码、访问控制或平台条款。
- 不把三个业务场景强行统一成完全相同的数据表和页面。
- 不提前拆微服务、建设插件市场或通用工作流语言。
- 不让 AI 自动执行删除、公开发布或其它高风险外部动作。

## 成功标准

- 新增一种来源时，主要修改集中在来源适配器。
- 更换抓取、队列、数据库或模型供应商时，业务模块接口保持稳定。
- 任一业务结论能回溯到任务、配置版本、原始证据和分析版本。
- 小规模项目可以简单部署，规模增长时无需重写领域模型。
