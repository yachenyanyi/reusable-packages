# 领域语言

统一语言比先设计数据库表更重要。以下词汇是模块之间共享的稳定语义。

## 来源与任务

- `Source`：允许系统观察的外部来源，如网站、模型渠道或社媒平台。
- `SourceProfile`：来源在某一版本的配置。
- `Task`：用户想持续回答的监测问题及其范围。
- `Run`：Task 的一次具体执行。

## 采集执行

- `Item`：一次 Run 中待完成的最小采集目标。
- `Attempt`：为完成 Item 进行的一次真实执行尝试。
- `CapturedArtifact`：采集运行时得到的原始数据及证据引用。
- `Observation`：核心确认的统一观察事实；扩展适配器先产生内部观察草稿，再由内容策略生成稳定对象身份。

Item 是“要完成的事”，Attempt 是“为了完成它做的一次尝试”。重试和回退增加 Attempt，不改变 Item 的身份。

## 内容历史

- `Document`：被持续观察的外部对象身份，不限于网页。
- `Snapshot`：Document 在某个时间点的不可变内容版本。
- `ChangeEvent`：相邻观察之间产生的新增、更新、失联、恢复等事实。
- `TypedEnvelope`：带命名类型和 schema 版本的扩展载荷，不等于无约束 JSON。
- `ContentPolicy`：某类内容的身份、规范化和修订比较规则。

## 分析与处置

- `AnalysisProfile`：关键词、规则、提示词和模型配置的版本化组合。
- `Finding`：系统根据证据发现的候选问题或值得关注的事实。
- `Case`：经过业务确认、需要分派和处置的工作对象。
- `Report`：按固定口径生成的可归档输出。
- `Alert`：面向特定接收策略的即时通知。

## 容易混淆的边界

- HTTP 404 是一次有效 Observation，可能产生“删除候选”；网络超时是 Attempt 失败。
- Finding 不是已经确认的 Case。
- Snapshot 是历史事实，不是可覆盖的当前业务记录。
- Source 描述“从哪里观察”，Task 描述“想观察什么”。
- 系统日志用于排障，AuditEvent 用于解释业务和安全动作。
- 上游记录身份用于投递去重，Subject 身份用于跨 Run 形成同一 Document，二者不能混用。
