# 技术验证记录

- 日期：2026-09-03
- 环境：Windows、Python 3.11.15
- 目的：在锁定实现前验证 HTTP、Playwright/CDP、正文解析和 Crawlee Python 的可用性。

## 已验证

- Python 3.11 可运行；
- `httpx 0.28.1` 可用；
- `playwright 1.62.0` 可用；
- `beautifulsoup4 4.15.0` 与 `lxml 6.1.1` 可用；
- 独立临时虚拟环境安装 `crawlee[playwright,beautifulsoup]==1.10.0` 成功；
- `BeautifulSoupCrawler`、`PlaywrightCrawler` 可导入；
- Crawlee 的 `run`、`add_requests` API 可反射检查。

## 发现的限制

- 单独安装 `crawlee` 后，访问可选 crawler 类会按需缺少 `bs4`、`playwright`、`browserforge` 等依赖；必须显式选择 extras。
- 安装 `crawlee[all]` 在 Python 3.11 环境中因 `opentelemetry-distro>=0.54` 没有可用版本而失败。
- Crawlee 的 `Request`、request queue 和 handler 模型适合实现抓取运行时，但不适合作为本组件的公共输入输出。

## 首版决定

首版把 Crawlee 作为候选技术和未来适配器，不把它作为必需依赖。公共实现使用：

```text
核心：Python 标准库 + 类型化领域契约
静态获取：HTTPX 适配器
动态获取：Playwright 适配器，支持独立浏览器或 CDP endpoint
解析：包内基于标准库 `HTMLParser` 的稳定解释器，不强制引入解析框架
frontier：组件内部有界异步队列
证据：文件系统或内存适配器
```

这样可以先验证真正的站点范围、重定向、分类和证据语义；如果后续需要 Crawlee 的并发、持久队列或反爬适配能力，只新增适配器，不改公共契约。

## 需要实站验证的风险

- 传统 CMS 的详情页和分页链接；
- `onclick`、`data-url` 和渲染后 DOM 的发现；
- 参数化平台子站的 host/path/query 边界；
- 静态响应到浏览器渲染的回退判定；
- CDP 断线、浏览器资源释放和大页面证据保存；
- 正文提取、发布时间和页面类型在五类代表站点上的准确度。

## 2026-09-04：远程 CDP 多站点验证

使用 win-03 的远程 Chromium CDP 节点，通过 PlaywrightAcquisition 和
WebsiteCollectionKit 对 12 个 high 官网进行了多轮小规模探测和定点复查：

- 国家超级计算无锡中心：传统 ASP.NET/CMS，验证新闻列表、新闻详情和机构详情；
- 江苏省未来网络创新研究院：验证渲染后的新闻、媒体和公示详情；
- 东南大学苏州医疗器械研究院：验证高校 CMS 的日期路径 page.htm 详情；
- 清华大学苏州汽车研究院：验证日期型新闻详情和机构简介；
- 长三角先进材料研究院：验证动态导航和附件发现；
- 江苏集萃先进激光科技有限公司、南京膜材料产业技术研究院有限公司：
  验证企业站的新闻、产品和方案页面；
- 专用集成电路技术研究所：验证 news.asp 栏目页与
  news_view.asp/news_views.asp 详情页的区分；
- 华进半导体封装先导技术研发中心有限公司：验证嵌套新闻详情；
- 江苏集萃安泰创明先进能源材料研究院有限公司：验证新闻列表与新闻详情；
- 长三角集成电路工业应用技术创新中心：验证带 UUID 查询参数的动态新闻；
- 东南大学苏州医疗器械研究院等大学子站：验证旧式列表页、详情页和正文容器。

本轮发现并修正了可跨站复用的问题：

1. 详情路由优先于公共导航词，避免页面里的“登录/联系我们”污染分类；
2. 识别 news_view.asp?id=...、嵌套新闻数字路径和高校日期型
   page.htm 详情；
3. 按路径段匹配，避免把 Research 误识别为 search；
4. 正文、标题和列表判断排除常见导航、页头、页脚、版权和隐藏节点；
5. 不把明显的 insert/create/update/delete/submit 写入接口作为候选页面；
6. 首页不再把首页中最新文章日期填充为首页的 published_at。

验证结果：

- 本地组件测试：52 项全部通过；
- 真实详情定点复查：页面均返回 HTTP 200，正文可提取，多个站点的发布时间可提取；
- 小规模全量回归：asictri 在 60 个候选中访问 39 个页面，
  aemcn 在 60 个候选中访问 40 个页面，均因预算达到上限而未收敛；
- nsccwx、aemcn 的列表页与详情页反例均保持正确区分；
- 发现队列、停止原因和盲区均通过 CoverageReport 返回，未将部分结果宣称为全站完整。

当前边界仍然有效：多个官网没有可用 sitemap，部分站点 robots 不可访问；
DOM、脚本和公开数据接口只能证明“观察到的候选”，不能证明网站绝对没有
漏页。生产运行仍应依据每站 Profile、预算和覆盖报告人工复核。

## 2026-09-04：内容页与覆盖度复核

在关闭代理的环境下，使用 HTTPX 对多个 high 官网进行实站复核，重点检查
“发现的 URL 是否是真实内容页”和“frontier 是否真的收敛”。本轮补充验证了：

- AEMCN：149 个候选、149 个访问、148 个成功页面，frontier 收敛；sitemap
  提供 121 个 URL，唯一失败为 `/hits` 的 404。结论是已覆盖观察到的发现源，
  不是绝对全站证明；
- IATTE：过滤 `data-target="_self"` 后为 73/73/73，frontier 收敛且无失败；
  `article-item-数字` 已识别为文章详情；
- IMRSZ：176/176/176，frontier 收敛且无失败；发现 88 组完全相同的
  HTTP/HTTPS 页面，生产 Profile 应明确首选协议，否则会浪费预算；
- NJIME：142/142/142，frontier 收敛，但 robots 和 sitemap 均不可用，只能把
  HTML/公开链接范围作为可证明覆盖；`post/数字` 已识别为文章详情；
- JCISTEC：52 个候选、52 个访问、46 个页面，存在一个公开接口 404，结果保留
  为 partial；行业、资源和合作页面均能作为内容页返回；
- AI-M：14/14/14，页面尾部的 NUL 缓冲区已清理，动态项目页不再产生空字符正文，
  但 sitemap 不可用；
- SICM：根路径查询键（如 `News/241.html`、`Overview/`）已参与分类；新闻旧文
  通过上一条/下一条形成长链，即使提高深度仍可能触及时限，不能按默认深度宣称
  历史内容完整。

根据上述复核，解释器新增了 NUL 清理、常见详情路由、根路径查询路由、窗口目标
值过滤、内容语义分类，以及 sitemap 超过安全条目上限时的盲区记录。覆盖报告继续
明确区分 `converged`、预算/时间耗尽和单页失败；`frontier_converged=true` 仍不
等于网站不存在未链接或隐藏页面。

## 2026-09-04：覆盖优先候选复核

针对“宁可多抓，不要漏抓”的原则，组件又补充了以下行为：

- 不再因为 URL 含有 `template`、`basic-template` 或其他未知 CMS 命名而在请求前排除；真实页面由响应正文和软 404 结果区分；
- 私有、登录和可能产生写入副作用的路由仍保留请求前安全排除，但改为按完整路由词匹配，避免把 `author` 等普通词误判为 `auth`；
- HTML 的 `rel=prev`、`first`、`last`、`up` 和同一 `onclick` 中的多个地址都进入发现 frontier；
- 增加压缩 sitemap 的集成回归，确认 gzip 内容能继续产生页面候选；
- 对 `showDetail`/`showBaseDetail` 这类只在脚本调用中保存文章 ID 的只读详情卡片，
  根据页面公开的栏目路由表恢复站内详情 URL；有外部地址的卡片仍作为站外来源处理；
- 修正 HybridAcquisition：只有 `PREFERRED` 模式允许静态失败后回退浏览器，`STATIC`
  模式不会隐式启用浏览器；
- 抓取成功但分类失败的页面保留为 `other`，正文和证据继续返回；疑似软 404
  也保留并继续参与链接发现，只通过问题标记提示后续分类或人工复核；
- 软 404 页面保留后仍会继续贡献页面链接，避免“错误入口页”挡住真实内容页；
- 组件回归测试为 107 项全部通过。

这只扩大了“观察到的公开候选”范围，不改变 Scope、robots、预算和不绕过访问控制的边界；候选发现收敛仍不能证明网站绝对没有隐藏页面。
