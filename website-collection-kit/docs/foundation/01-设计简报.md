# 设计简报

- 状态：首版已按本简报实现并完成本地验收
- 日期：2026-09-03

## 任务

建立一个可独立理解和复用的网站检查与内容采集组件，为统一采集 API 提供底层能力，并首先服务长三角网站监测项目。

## 复杂度目标

- 把网站结构差异、链接发现、URL 规范化、抓取方式选择、失败回退、内容提取和覆盖评估隐藏在组件内部。
- 让调用方只表达“检查站点”“采集站点”或“定点复查”，不编排抓取步骤。
- 让新增普通网站主要增加或调整 Site Profile，不修改核心流程。
- 让更换 HTTP、Playwright/CDP、队列或存储实现时，公共结果契约不变。
- 明确“覆盖情况”与“穷尽所有页面”不是同一承诺，避免形成无法兑现的隐含需求。

## 候选设计

### 方案 A：框架直接成为公共模型

统一 API 直接创建 Crawlee/Playwright crawler，调用方传队列、并发、浏览器开关、处理器和框架 Request；采集结果直接使用框架对象。

- 优点：原型快，框架能力使用直接。
- 缺点：框架概念向上传播；更换框架会影响 API、配置和测试；网站策略散落在 handler 中。
- 结论：拒绝作为长期边界，可用于适配器内部。

### 方案 B：按执行步骤拆成许多公共模块

公开 `SeedDiscovery`、`UrlNormalizer`、`Frontier`、`Fetcher`、`Parser`、`Classifier`、`CoverageEvaluator`，调用方按顺序组装。

- 优点：每个步骤容易单独理解和替换。
- 缺点：接口总量接近实现复杂度；调用方承担顺序、重试和中间状态；容易形成透传方法和透传变量。
- 结论：拒绝作为公共 API。这些概念可以成为包内协作者，但不能把协调负担交给调用方。

### 方案 C：意图接口加深模块

公开一个稳定门面，提供 `inspect_site`、`collect_site`、`refresh_pages` 三个意图操作。内部由站点探索、采集执行、内容解释和证据处理协作；具体抓取器和证据存储通过端口接入。

- 优点：公共表面小；网站和供应商差异被隐藏；部分失败、回退和覆盖口径只有一个所有者。
- 缺点：组件内部实现更复杂；需要高质量契约测试以防止适配器语义漂移。
- 结论：选择。

## 候选模块和接口

### WebsiteCollectionKit

- 目的：作为最深模块，可靠完成一次网站检查或采集意图。
- 公共操作：`inspect_site`、`collect_site`、`refresh_pages`。
- 输入：一个版本化规格，其中包含 Site Profile 已解析快照以及调用方真正拥有的范围与预算。
- 输出：`SiteInspection` 或 `CollectionResult`。
- 错误：仅抛出无法开始或无法解释整体结果的任务级错误；单页失败进入结果问题列表。
- 副作用：访问公开网站，通过已装配端口保存证据和可恢复状态。
- 不变量：不越过允许范围；同一规范 URL 在一次运行中最多形成一个主结果；终止时报告停止原因。
- 调用方责任：提供合法站点身份、采集范围、Profile 版本和合理预算；保存并使用返回结果。
- 隐藏知识：种子发现、队列、分页、抓取选择、重试、回退、DOM 处理、去重、分类和覆盖评估。
- 非目标：历史版本、变化识别、业务分析和统一 API 的 Job 生命周期。

### AcquisitionPort

- 目的：隔离 HTTP、浏览器和 CDP 等获取技术。
- 公共操作：按包内获取要求取得资源；未完成的 `fetch` 通过宿主语言的结构化任务取消，不增加一个没有独立语义的 `cancel()` 透传方法。
- 输入输出：包内稳定类型，不接受或返回 Playwright、Crawlee、HTTP 客户端对象。
- 隐藏知识：连接、会话、超时、供应商状态码映射、浏览器上下文和资源清理。
- 调用方：仅由组件内部编排器使用，由应用启动时显式装配。

### EvidencePort

- 目的：保存原始响应、渲染后 DOM、截图或附件，并返回稳定证据引用。
- 不变量：返回引用前证据已持久化；敏感数据按运行策略清理。
- 非目标：长期网页版本模型和报告归档。

## 选型理由

- 最深模块是 `WebsiteCollectionKit`，它以三个操作隐藏完整站点遍历与采集协调。
- 公共接口不暴露队列、游标、重试次数、浏览器开关、CSS 选择器执行顺序或框架对象。
- 传输层只做请求/响应翻译；本组件拥有采集语义；适配器拥有技术产品差异；`monitoring-kit` 拥有运行可靠性与内容历史。
- 站点特例集中在版本化 Profile 或显式注册策略，不能散落在调用方条件分支中。

## 泄漏与透传审计

- 禁止公共字段：`use_playwright`、`cdp_url`、`request_queue`、`retry_count`、`browser_context`、供应商错误码。
- Site Profile 可以声明“内容需要渲染”等站点事实，但不携带 CDP 地址、代理账号或任意脚本。
- API Job 游标属于统一采集 API；内部 URL frontier checkpoint 不得冒充公共 API 游标。
- 不创建与门面同名同参数的 `Service`、`Manager`、`Controller` 透传链。
- URL 规范化、范围判定和重定向越界只有一个策略所有者。

## 尚存权衡

- Site Profile 表达能力过弱会产生代码特例，过强会变成不安全的脚本平台；第一版只允许声明式规则和已注册策略标识。
- “自动发现”无法证明全站穷尽；通过多来源发现、收敛信号和覆盖报告把不确定性显式化。
- 具体语言和框架仍需代表性网站原型决定，但不能反向改变领域契约。
