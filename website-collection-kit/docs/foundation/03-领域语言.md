# 领域语言

## 核心概念

### Site

一次检查或采集所针对的逻辑网站。它可能使用多个允许 host，也可能是平台域名下的一个路径或参数化子站，因此不能简单等同于注册域名。

### Site Scope

调用方允许本次操作访问和产出结果的边界，包括种子、允许 host、路径/参数约束、站外链接策略和资源预算。范围必须先于遍历确定。

### Site Profile

对某个网站稳定结构事实的版本化描述，例如入口、范围规则、路由模式、渲染需求、字段提示和排除规则。Profile 是输入快照，不是本组件管理的长期资产。

### Site Inspection

为认识一个网站结构而进行的有界操作。结果包括候选页面、分类、发现来源、排除记录、覆盖信号和 Profile 草案；它不等于正式内容入库。

### Collection

一次有明确站点、范围、意图和预算的内容采集。Collection 是本组件概念，不等于 `monitoring-kit` 的 Run，也不等于统一 API 的 Job。

### Page Candidate

发现但尚未必然采集的页面候选。它记录原始 URL、规范 URL、发现来源、推测类型和范围判定。

### Website Page

成功解释后的标准网页记录。它代表一次观察结果，不代表长期页面实体或历史快照。

### Fetch Evidence

支持采集结论的原始材料引用，如响应体、响应头、渲染后 DOM、必要截图或下载附件。公共结果返回引用，不承诺把大对象内嵌在记录中。

### Coverage Report

说明本次操作看到了哪些发现来源、访问了多少候选、为何停止、有哪些失败和仍存哪些盲区。它表达证据和不确定性，不宣称数学意义上的完整率。

### Exclusion

候选未进入正式采集的可解释原因，例如越界、robots 禁止、重复、登录页、搜索组合爆炸、媒体资源或 Profile 排除。

## 三种公开意图

- `inspect_site`：认识站点结构并形成 Profile 草案。
- `collect_site`：按确定范围采集网站内容，内部自行完成必要发现。
- `refresh_pages`：只复查一组明确 URL，用于整改复核、失效确认或高频页面刷新。

这三个意图不是要求调用方依次执行的流水线。正式采集可以直接调用 `collect_site`；已有 Profile 时无需先检查。

## 身份区分

```text
site_ref             外部资产系统中的网站身份
collection_id        本组件一次调用的身份
canonical_url        本次解释得到的页面规范地址
evidence_ref         原始证据身份
monitoring run_id    monitoring-kit 的可靠运行身份
upstream_job_id      统一采集 API 的任务身份
```

这些身份不可互换。`canonical_url` 是页面身份的重要输入，但最终 Document 身份由 `monitoring-kit` 决定。

## 时间语义

- `observed_at`：组件实际观察页面的时间；
- `published_at`：页面内容声明的发布时间，可能缺失或置信度较低；
- `modified_at`：页面声明的更新时间，可能缺失；
- `first_seen_at`、`last_seen_at`：属于长期历史系统，不由本组件生成。
