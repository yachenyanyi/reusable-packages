# 覆盖优先的候选保留

## 背景

网站发现阶段最危险的错误不是多产生几个 404，而是把一个真实内容页在请求前误判为模板页、占位页或“看起来不像内容页”的 URL。旧式 CMS 经常把真实页面放在名称含有 `template`、数字、查询参数或非典型后缀的路径下。

## 决策

`website-collection-kit` 采用“覆盖优先、安全边界不放松”的候选策略：

- 通过 Scope、robots、协议、host、路径和查询键校验的 URL，默认进入 frontier；
- 仅把明确的登录、私有接口和可能产生写入副作用的路由作为请求前排除；
- `template`、`basic-template`、占位词、未知 CMS 路由和页面类型猜测不得单独造成请求前排除；
- 这些 URL 由正常获取、正文解释和软 404 识别来判断，结果中的候选、问题和覆盖信息保留可追溯关系；
- `rel=prev`、`first`、`last`、`up` 和一个脚本处理器中的多个页面地址都作为发现线索保留。

## 被拒绝的方案

### 按词过滤模板路径

在请求前排除所有包含 `template` 或“基础模板”的 URL，能减少少量无效请求，但会把“模板命名的真实内容页”直接变成漏抓。为每个网站增加白名单也会把通用误判转化为 Profile 维护负担。

### 取消所有请求前安全过滤

把登录、私有接口和可能写入的路由也交给普通页面队列，会扩大访问风险，并且不符合组件不绕过访问控制、不修改目标网站的边界。

## 结果与取舍

选择“覆盖优先、安全边界不放松”的候选保留方案。候选数、404 数和重复数可能增加，但它们会体现在 CoverageReport 中；未知 URL 不再因为通用启发式而静默消失。页面数、候选数、深度、时长和 robots 仍然是硬边界，因此“多抓”不会变成无界爬虫。

## 验收

- 含 `basic-template` 的真实公开页面必须能够进入结果；
- 详情页的 `rel=prev` 必须能够继续发现更早页面；
- 同一 `onclick` 中的多个页面地址不得只保留第一个；
- 私有、登录和写入风险路由仍保持请求前排除；
- 所有组件测试通过，且部分结果仍不能被表述为绝对全站完整。
