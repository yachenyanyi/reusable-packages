# 检查与采集流程

## 站点检查

```text
检查规格 + 可选现有 Profile
        ↓
建立允许范围和资源预算
        ↓
读取主页 / robots / sitemap / RSS
        ↓
抽样导航、栏目、列表、分页和详情
        ↓
必要时观察渲染 DOM 与公开网络线索
        ↓
规范化、分类、排除和结构推断
        ↓
SiteInspection + CoverageReport + ProfileDraft
```

检查是有界抽样，不默认下载整个站点。它的目标是认识入口、路由族、页面类型、渲染要求和明显盲区，为正式采集提供可审查的 Profile 草案。

## 站点采集

```text
采集规格 + 已冻结 Profile 快照
        ↓
建立 frontier 并合并发现来源
        ↓
范围判定与规范化去重
        ↓
获取资源 → 解释内容 → 保存证据 → 产生页面结果
        ↑                         ↓
        └──── 新的站内候选 URL ──┘
        ↓
队列收敛 / 预算耗尽 / 取消 / 致命失败
        ↓
CollectionResult + CoverageReport
```

调用方只发起采集意图，不参与中间循环。框架队列和恢复检查点是内部状态，不成为公共分页游标。

## 发现来源

第一版按以下信号组合，不把任何单一来源当作完整清单：

- 显式种子和主页；
- `robots.txt` 指向的 sitemap；
- sitemap index 与 URL set；
- RSS/Atom；
- 静态 HTML 的链接和安全可解析导航属性；
- 渲染后 DOM 的链接；
- 导航、栏目、列表和分页形成的路由族；
- 页面暴露的公开 XHR/JSON 列表线索；
- 调用方提供的已知历史 URL。

站外 URL 默认只记录为 `outbound_source`，不递归采集。附件按 Profile 和允许类型单独处理。

## 获取策略

公共调用方不选择 HTTP 或浏览器。组件根据 Profile、响应和内容可用性做内部决策：

1. 优先使用成本较低且证据稳定的获取方式；
2. 当页面声明需要渲染，或静态响应缺少预期内容且满足回退条件时，使用渲染适配器；
3. 回退次数有限且可观测，不能在两种方式间无限切换；
4. CDP 连接、浏览器上下文、代理和凭证仅存在于适配器与宿主配置；
5. 登录、验证码或明确访问限制转为可解释失败，不尝试绕过。

具体阈值是运行策略或 Profile 事实，不进入公共操作参数。

## URL 规则

- 在请求前和重定向后都执行范围判断；重定向不能借机越界。
- 页面 Scope 与浏览器资源网络策略分开：页面只能进入声明范围，渲染所需的公开子资源可按适配器网络策略加载但不会进入 frontier。
- 默认网络策略只允许公开 HTTP/HTTPS 的 GET/HEAD，并拒绝 loopback、私网、link-local、metadata 等地址；生产 DNS rebinding 防护仍由受控 DNS 和出口网络提供。
- fragment 默认不参与网络身份；有真实 hash-route 网站时由具名策略处理。
- 参数不能一律删除。跟踪参数、排序参数、分页参数和内容身份参数必须区分。
- 实际 `request_url` 与用于去重的 `canonical_url` 分开保存；canonical 化不能无条件改写 wire 请求，等价请求地址作为 alias 保留。
- canonical 标签是证据之一，不无条件信任；跨 host canonical 必须符合范围规则。
- 搜索、日历和无限筛选组合应有组合爆炸保护。
- 同一规范 URL 的不同原始来源保留发现关系，但一次 Collection 只产出一个主页面结果。

## 页面解释与分类

通用解释器结合 URL、导航位置、DOM 结构、结构化数据、标题、时间和正文密度判断页面类型。Profile 可以提供声明式提示，但不能直接注入任意代码。

第一版稳定分类：

```text
home, list, news_list, notice_list, article, notice,
profile, research, product, recruitment, contact,
attachment, search, login, other
```

分类必须同时返回置信度和依据。无法可靠分类时使用 `other`，不以猜测制造确定性。

## 部分失败与停止原因

- 单页超时、解析失败、robots 禁止、越界重定向和不支持内容类型写入问题或排除记录，不默认使整个 Collection 失败。
- 输入无效、Profile 不兼容、所有获取适配器不可用或证据系统无法满足必需持久化时，才产生任务级失败。
- 预算耗尽返回可用的部分结果和明确停止原因，不伪装成完整成功。
- 取消后返回已经完成且证据已持久化的结果，并标明取消终态。

## 覆盖口径

Coverage Report 至少说明：

- 使用和缺失的发现来源；
- 候选、访问、成功、失败、排除和重复数量；
- 各页面类型与主要路由族的样本；
- sitemap 是否遍历完成、frontier 是否收敛；
- 是否触发页面数、深度、时间或请求预算；
- 是否触发总请求数、总响应字节数或渲染页预算；
- robots、登录、脚本渲染、接口失败等已知盲区；
- `converged`、`budget_exhausted`、`cancelled` 或 `failed` 等停止原因。

不得输出无法解释的单一“覆盖率百分比”。后续若有已知 URL 基线，可以额外计算相对于该基线的召回率，但必须标明基线来源。
