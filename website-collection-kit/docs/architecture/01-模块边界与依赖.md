# 模块边界与依赖

## 目标结构

以下是出现真实代码后的目标布局，不要求现在提前创建空目录：

```text
src/website_collection_kit/
├─ __init__.*                 # 只导出承诺兼容的门面和公共契约
├─ contracts/                 # 版本化输入、输出、错误和值对象
├─ inspection/                # 深模块：站点检查与 Profile 草案
├─ collection/                # 最深模块：完成站点或定点采集意图
├─ interpretation/            # 页面内容解释与分类策略
├─ profiles/                  # Profile 校验、匹配和已注册策略协议
├─ ports/                     # 获取、证据、检查点等被核心需要的端口
└─ adapters/
   ├─ http/
   ├─ playwright_cdp/
   ├─ crawling_framework/
   └─ evidence/
```

目录按“拥有哪类易变知识”划分，不按 `parser/validator/processor` 的执行顺序机械拆分。简单实现可以合并文件；只有独立不变量或依赖隔离出现时才拆模块。

## 深模块

`collection` 是最深模块。它接受一次采集意图并返回完整结果，内部隐藏：

- 种子扩展和 frontier；
- URL 规范化、去重与范围判定顺序；
- sitemap、RSS、HTML、渲染 DOM 和公开 JSON 线索的组合；
- 静态与渲染获取选择、有限回退、重试和资源清理；
- 页面解释、分类、证据写入和部分失败；
- 预算耗尽、队列收敛和覆盖报告生成。

调用方不应逐步调用这些内部能力。`inspection` 可独立使用，因为“认识站点并产出 Profile 草案”是独立业务意图，而不只是采集第一步。

## 依赖方向

```text
统一 API / CLI / 应用装配
        ↓
公共门面与 contracts
        ↓
inspection / collection ──→ interpretation / profiles
        ↓
       ports
        ↑
具体 HTTP / Playwright-CDP / 框架 / 证据适配器
```

- 核心模块声明自己需要的端口，但不导入适配器。
- 适配器依赖端口和稳定契约，不互相依赖。
- 应用启动时显式选择并装配适配器，不使用自动扫描或导入副作用。
- 本组件不得导入 `apps/长三角监测`。
- 若 `monitoring-kit` 依赖本组件，只能依赖文档化公共 API；更推荐由统一 API 宿主装配二者，避免库间形成不必要耦合。

## 各模块隐藏的知识

### inspection

拥有发现信号组合、抽样深度、站点结构推断、候选分类和 Profile 草案生成。它不拥有正式 Job、网页历史或 Profile 发布流程。

### collection

拥有一次采集内的遍历不变量、预算、失败聚合、回退和结果完整性。它不拥有跨运行调度与恢复策略；若需要长运行检查点，通过端口保存，由宿主决定生命周期。

### interpretation

拥有从响应/DOM 到 `WebsitePage` 的语义转换、通用字段候选和置信度。它不访问网络、不管理 frontier，也不决定 AI 风险。

### profiles

拥有 Profile schema 校验、规则匹配和策略注册约束。它不管理客户 Profile 数据库、审批或 UI。

### adapters

拥有框架、协议、浏览器、CDP、对象存储和供应商异常。适配器不得自行改变站点范围或推进业务 Job 状态。

## 禁止的浅层结构

- `WebsiteController → WebsiteService → WebsiteManager → Crawler` 的同形透传链；
- 为每个网站建立一个 Python/TypeScript 模块；
- 暴露 `enqueue`、`fetch`、`parse`、`classify` 给普通调用方并要求固定顺序；
- 将 Playwright `Page`、HTTP Response、Crawlee Request、数据库行或框架异常放入公共契约；
- 创建全局 `utils`、`common`、`services`、`managers` 或任意 JSON `metadata` 垃圾桶。

## 拆分门槛

只有出现独立发布、明显重型依赖、独立扩缩容、不同团队所有权或第二种真实消费方式时，才把适配器或解释器拆成单独发布包。CDP 节点是基础设施部署单元，不因此自动成为新的领域组件。
