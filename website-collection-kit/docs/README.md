# website-collection-kit 文档

## 文档目的

这组文档先约束组件的职责、语言和接口，再指导实现。发生冲突时，优先级为：仓库 `AGENTS.md`、本组件范围文档、公共契约、架构说明、实现细节。

## 阅读顺序

1. [设计简报](foundation/01-设计简报.md)：复杂度目标、候选设计和选型理由。
2. [范围与非目标](foundation/02-范围与非目标.md)：组件负责和明确不负责的事项。
3. [领域语言](foundation/03-领域语言.md)：统一概念及其生命周期。
4. [模块边界与依赖](architecture/01-模块边界与依赖.md)：代码所有权、深模块和依赖方向。
5. [检查与采集流程](architecture/02-检查与采集流程.md)：端到端语义、失败和覆盖口径。
6. [Site Profile](architecture/03-Site-Profile.md)：网站差异的数据化表达方式。
7. [公共契约](contracts/01-公共契约.md)：实现前必须稳定的输入、输出和错误。
8. [初始架构决策](decisions/0001-初始架构决策.md)：已选方案、拒绝方案和演进门槛。
9. [开发路线与验收](development/01-开发路线与验收.md)：按风险排序的实现阶段和完成标准。
10. [技术验证记录](development/00-技术验证记录.md)：Python、HTTP、浏览器和 Crawlee 的实际验证结果。
11. [使用示例](development/02-使用示例.md)：直接调用、浏览器装配、探测和定点复查。
12. [覆盖优先的发现与分类调整](decisions/0002-覆盖优先的发现与分类调整.md)：降低动态站点的漏抓与误分类。
13. [覆盖优先的候选保留](decisions/0003-覆盖优先的候选保留.md)：请求前过滤的安全边界与漏抓控制。
14. [GitHub Issue 修复计划](development/03-GitHub-Issue修复计划.md)：#7–#12 的职责归属、依赖顺序、契约选择和验收门槛。

## 文档维护规则

- 公共接口、依赖方向、Profile 能力或职责归属改变时，先更新设计简报和对应文档。
- 单个网站的规则写入项目自己的 Profile，不在公共文档中增加客户特例。
- 没有代码和真实用例前，不创建空目录、占位接口或未来功能文档。
- 技术产品的使用手册跟随具体适配器；领域契约不引用供应商 DTO。
